# tracr 📦

**Stop losing track of your stash.**

Tracr is a Flutter web app for collectors who buy, hold, and sell physical
collectibles (TCG cards, Funko Pops, sealed boxes, and anything else you'd
grade, slab, or shelve). It brings your wishlist, your sellers, your
in-transit packages, and your vaulted collection into one dashboard, so
nothing gets lost between "I want this" and "it's on my shelf."

## Features

- **Wishlist** — track things you want to buy, with priority, target price,
  and source links.
- **Stash** — items that are bought and paid for but not yet in hand.
- **Tracking** — shipments in transit, with courier deep-links (J&T, LBC,
  Ninja Van, Flash Express, JRS) and stale-delivery detection.
- **In Hand** — your physical collection, organized into containers
  (binders, deck boxes, toploader cases, display shelves, storage boxes,
  safes) with per-container item counts and value rollups.
- **Sellers** — a lightweight seller directory tied to your purchases and
  shipments.
- **Flexible item attributes** — label/value pairs let the item form adapt
  to whatever kind of collectible you're tracking (set/number for cards,
  pop number for Funko, edition for sealed product) instead of hardcoding
  one schema.
- **Grading & condition** — track raw condition (NM–DMG) or graded slabs
  (PSA/BGS/CGC) with cert numbers.
- **Google sign-in**, email verification, and a short onboarding flow.

## Tech stack

- [Flutter](https://flutter.dev/) (web)
- [Riverpod](https://riverpod.dev/) for state management
- [go_router](https://pub.dev/packages/go_router) for routing, driven by
  auth/profile/onboarding state
- [shadcn_ui](https://pub.dev/packages/shadcn_ui) for the component library
- [Firebase](https://firebase.google.com/) — Auth, Cloud Firestore, and
  Storage

## Getting started

### Prerequisites

- [Flutter SDK](https://docs.flutter.dev/get-started/install) (Dart ^3.12.2)
- A Firebase project with Auth, Firestore, and Storage enabled
- The [FlutterFire CLI](https://firebase.google.com/docs/flutter/setup)

### Setup

```bash
# Install dependencies
flutter pub get

# Generate lib/firebase_options.dart for your own Firebase project
# (this file is gitignored — you need to run this once locally)
flutterfire configure

# Run the app
flutter run -d chrome
```

Firestore security rules and indexes live in [firestore.rules](firestore.rules)
and [firestore.indexes.json](firestore.indexes.json); storage rules live in
[storage.rules](storage.rules). Deploy them with the Firebase CLI:

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage
```

## Project structure

The app follows a feature-first layout under `lib/`:

```
lib/
├── core/            # Shared shell, router, theme, and layout widgets
├── features/
│   ├── auth/        # Sign-in, email verification
│   ├── onboarding/  # First-run setup flow
│   ├── profile/     # User profile
│   ├── collectibles/  # Dashboard
│   ├── wishlist/    # Items you want
│   ├── stash/        # Bought, not yet received
│   ├── tracking/     # Shipments in transit
│   ├── inhand/        # Owned items & storage containers
│   ├── containers/     # Container CRUD
│   ├── items/          # Core item model, CRUD, search
│   └── sellers/        # Seller directory
├── firebase_options.dart  # Generated by flutterfire (gitignored)
└── main.dart
```

Each feature is split into `data/` (repositories), `domain/` (models), and
`presentation/` (pages/widgets) as applicable.
